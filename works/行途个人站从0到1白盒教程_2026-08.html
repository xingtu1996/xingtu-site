提示词（boss）「我要买 1 个域名」+ 指南转发；「考虑长远 + MVP 双轨，关心免费方案和坑」

2域名调研：核实指南 + 撞名证据链
AI 工具WebSearch×3 并行（续费价/实名范围/隐私保护）＋WebFetch（抓 xingtu.com/.cn 身份）＋Bash whois（批量查占用）
skill无（纯 Web + 终端）
关键命令 
whois -h whois.nic.google xingtu.dev        # 查 Google 系后缀
whois xingtu1996.com                          # 查 .com
curl -s https://rdap.nic.google/domain/xingtu.dev   # RDAP 标准接口
关键发现xingtu.com=兴图新科；xingtu.cn=字节巨量星图；拼音 xingtu 撞 兴图/星途/星图 → 高度拥挤
白盒点：whois 是注册局的真实数据库，不是注册商「建议页」（Spaceship 那页全是溢价 upsell）；RDAP 是 ICANN 标准 HTTP 接口，whois 服务器不通时的替代。

6授权与推送：gh + SSH 双通道
skillgithub（gh CLI）+ agent-browser（登录表单，最终因沙箱限制由 boss 手动）
关键命令 
# 授权（走代理，因为直连 github.com 不通）
HTTPS_PROXY=http://127.0.0.1:7897 gh auth login -h github.com
echo 'github_pat_...' | gh auth login --with-token -h github.com   # 备选：PAT 方式
GH_HOST=github.com gh repo create xingtu1996/xingtu-site --private   # 建仓（强制走 github.com）
ssh -T git@github.com                                                # SSH 验证
git push -u origin main                                              # 推送（SSH 走 443+代理）
坑gh 默认走公司主机（github.cn-pgcloud.com）→ 必须 GH_HOST=github.com；设备流需 POST github.com → 直连超时 → 走代理或 PAT
白盒点：这台机器「直连 github.com 不通、走 127.0.0.1:7897 代理通」（curl 实测 000 vs 200）；SSH 用 443 + ProxyCommand 已配好 → 推送走 SSH 最稳。
7Cloudflare Pages 部署：API 建项目 + wrangler 上传
AI 工具Bash curl（验证 token / 建项目）+ wrangler（部署）
关键命令 
curl "https://api.cloudflare.com/client/v4/user/tokens/verify" -H "Authorization: Bearer $CF_TOKEN"   # 验 token
ACCT_ID=$(curl -s "https://api.cloudflare.com/client/v4/accounts" -H "Authorization: Bearer $CF_TOKEN" | grep -oE '"id":"[a-f0-9]{32}"' | head -1 | cut -d'"' -f4)
curl -X POST "https://api.cloudflare.com/client/v4/accounts/$ACCT_ID/pages/projects" \
  -H "Authorization: Bearer $CF_TOKEN" -H "Content-Type: application/json" \
  -d '{"name":"xingtu1996","production_branch":"main"}'
CLOUDFLARE_API_TOKEN=$CF_TOKEN npx -y wrangler pages deploy . --project-name=xingtu1996
坑token 缺 Account Settings Read → wrangler 列不出账号；wrangler 4 首次建项目非交互报错 → 先 API 建项目再 deploy
白盒点：wrangler「自动识别账号」= 调 GET /accounts；token 权限决定它能不能看到账号。看懂 API 依赖，就知道为什么报错、怎么解。

curl -s https://xingtu1996.pages.dev | head   # 返回真实首页内容

三、白盒要点速查（为什么）

现象原理
直连 github.com 报错网络直连 000，走 127.0.0.1:7897 代理 200 → 浏览器/gh 都要代理或走 SSH 443
gh 建仓跑公司服务器gh 默认取「active 主机」→ 用 GH_HOST=github.com 强制
wrangler 报「列不出账号」token 缺 Account:Account Settings:Read → 加权限或显式 CLOUDFLARE_ACCOUNT_ID
wrangler 非交互报错首次部署要「确认建项目」→ 先用 API 建好项目再 deploy
浏览器自动关闭沙箱在命令结束回收后台进程 → 跨命令自动化不可行，改单命令或人工
改名后旧链接 404GitHub 官方规则：旧用户名释放、旧主页永久 404
为什么 1996 不进显示名显示名=给读者记；handle=唯一标识层，两层职责不同

九、发布原理：不可变快照（白盒）

原理每次部署 = 一个不可变版本（类似 git commit）；Cloudflare 无服务器进程，文件存在边缘存储、全球 300+ 节点代为分发
专属 URL每次部署生成唯一地址（如 cd719a2c.xingtu1996.pages.dev），永久可访问，可回滚
白盒点：「发布」不是覆盖文件，而是「上传新快照 + 切换 production 指针」。这就是为什么改坏了能一键回滚，比 FTP 覆盖安全一个量级。

十、自定义域名绑定流程

前提先买真域名：xingtu.dev（~$12–15/年，大厂背书）或 xingtu1996.com（国内可备案）
步骤
  1. 控制台 → Workers & Pages → xingtu1996 → Custom domains → Add custom domain；
  2. 输入域名（如 xingtu.dev）→ 若 DNS 已在 Cloudflare 托管：自动加记录，等几分钟验证；
  3. 若 DNS 在别处（Namecheap/腾讯云等）：按提示加一条 CNAME：xingtu.dev → xingtu1996.pages.dev；
  4. 验证通过 → Cloudflare 自动签发 HTTPS 证书 → 生效；
  5. 可选：设为主域，pages.dev 保留或 301 重定向过去。
白盒点：自定义域的原理 = DNS 把域名「指到」Cloudflare，证书由 CF 自动管理（免费）；免备案（服务器在境外）。国内搜一搜 SEO 需另买 .cn 走 ICP 备案（7–20 天）。

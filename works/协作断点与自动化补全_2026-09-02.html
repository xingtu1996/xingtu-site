协作断点与自动化补全诊断

行途 · 2026-09-02 · 基于 4 篇已读成稿 + 资产台账 + 9 次协作会话综合 · 单文件零依赖
⚠️ 先纠正一个我之前的错误判断。 前两份看板里我写「成稿→发布 0%」「产能出口堵塞」。 但你明确说公众号「编辑素材 / 制作封面 / 定时发布 / 微信贴图」已跑通——说明文章真实发出去了。 所以真相不是「没发」，而是：发了，但发出去的内容没有回流到我们的协作闭环里。 本地成稿无「已发布」标记、台账「最近活跃」为空、全仓搜不到任何 mp.weixin 链接。 「0%」是我用本地文件当真实发布率的误判，特此更正。

一、协作闭环：跑通 vs 断点

① 选题挖掘（素材卡 1161）→ ② 成稿（4 篇，质量高）→ ③ 成稿→发布稿定稿→ ④ 推送公众号→ ⑤ 发布回流 / 复盘
✅
① 选题挖掘 — 已跑通且超额（1161 卡）
✅
② 成稿 — 4 篇均为产品级（带大纲/配图建议/平台微调/脱敏）
⛔
③ 定稿 — 成稿≠发布稿，配图未产出、数字未同步
⛔
④ 推送 — API 权限未实调，路线未定
⛔
⑤ 回流 — 发了没回来，闭环断在此

结论：我们的瓶颈不在「生产」，在「生产之后到发布」和「发布之后回环」两段。这两段恰恰是自动化最容易补、且不需要 n8n 这类重编排的地方（见第四节）。

二、5 个协作断点（均来自实读证据）

断点 1 · 成稿数字与素材库脱节（实锤）

出处原文真实值性质
B11 第48行「现在有 76 张卡，覆盖 12 个分类」素材库 JSON = 1161 张（实测）过期
M01 第24行「沉淀出 1100+ 张可发布素材卡」约数
能力模型看板「1161 张素材卡」准确

同一批成稿出现 76 / 1100+ / 1161 三数——铁证：成稿写完后素材库在涨，成稿的数字没同步。违反「单一事实源」原则。这是纯本地问题，立刻可修。

断点 2 · 成稿 ≠ 发布稿

4 篇成稿结构一致：大纲 + 配图建议 + 平台微调 + 脱敏确认。这是创作稿，不是发布稿。中间缺一道「定稿」工序：把大纲展开成正文、把长标题压到 ≤15 字防折叠、按平台微调拆版。目前这道工序靠你在公众号后台手动做。

断点 3 · 配图 / 图解未产出

每篇都写「配图建议（XXX 图）」——图还不存在。你的 render_wechat.js 截图链路已跑通，但这些成稿的图没接上。B11 直接嵌 mermaid（第52行），而 RULES 铁律是「mermaid 必须转图」——成稿阶段铁律未执行。

断点 4 · 已发布无回流（最致命）

文章发出去后，链接 / 发布时间 / 阅读·转发·完读数据 / 复盘 全没回到本地。后果：① 我无法基于真实数据优化下一篇；② 能力模型看板「外显率」只能估；③ 你发得越多，本地越「瞎」。这是闭环断在最后一环。

断点 5 · 微信贴图线零留痕

你说「微信贴图已跑通」——但全仓搜不到任何贴图/表情资产记录。这条产品线（微信表情开放平台）同样没有回流档案，与断点 4 同构。

三、已发布文章，我能看什么 / 不能看什么

我能直接观察的（本地）

  • 4 篇成稿：形态、SEO 埋词、平台微调、脱敏等级——已读完，质量高。
  • 选题矩阵：M01/B02/B11 构成「方法+实证+理念」三角，设计是对的。
  • 协作脉络：9 次会话从变现路径→对标→能力模型→素材接收→工作流选型，方法论已成型。

我看不到的（需你回流）

  • 公众号后台真实文章（mp.weixin 链接抓不到）、阅读/转发/完读/常读数据。
  • 哪些成稿真发了、哪些没发、读者反馈。

解法：你发完把链接 + 日期丢给我（或直接导出公众号文章备份），我建「已发布文章档案」回填台账并做复盘。模板见 xingtu-vault/09_个人台账/03_已发布文章档案/。

四、自动化补全方案（轻量本地优先，呼应「不上 n8n」结论）

优先级动作解决断点依赖工作量
P0成稿数字同步：成稿里 {{card_count}} 等占位符，渲染时从素材库 JSON 注入最新值断点1纯本地~30 行
P0发布回流档案：每篇发完回填链接/时间/数据/复盘，自动更新台账「最近活跃」断点4/5你丢链接模板已建
P1成稿→发布稿定稿脚本：render_wechat.js 展开正文 + mermaid 转图 + 配图截图 + 标题压 ≤15 字断点2/3本地脚本~80 行
P1API 权限实调：跑 curl 定 draft/add 是否 48001，决定发布路线（API vs Playwright）断点4AppSecret1 命令
P2定时任务心跳巡检：15 行脚本 + 飞书 bot，超 48h 无心跳告警（治「失效不可见」）全局feishu_bot~50 行

原则：只把确定性环节脚本化（定稿、同步、回流、巡检），判断性环节（蒸馏脱敏、选题立项）保持人+AI 协作，不塞进固定编排。这是昨天「不上 n8n」结论的延续。

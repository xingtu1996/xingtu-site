① 专家总论：四个空间不是文件夹，是自媒体资产运营中枢

你现在的体系解决了"内容怎么生产"（02 仓库 / 03 工具箱 / workflows SOP）。但缺的是把生产前置（调研）、生产外溢（开源）、资产沉淀（台账）、资产自有化（独立站）这四块收口。补上 07–10，xingtu 才从"内容文件夹"升级成"自媒体资产运营系统"。

🟣 07 调研 — 给生产供料

解决"选题拍脑袋、热点追不上、工具链看不清"。每条调研必须落"可发选题"，喂给 02 灵感池。

🟢 08 开源 — 给 IP 背书

解决"作品集空泛"。开源是信任锚 + 反向引流钩子 + B2B 顾问背书（FEN-006）。

🟠 09 台账 — 给资产体检

解决"账号散、到期忘、收入糊"。账号/域名/收入/凭据全部台账化，每月盘点。

🔵 10 站点 — 给自己留地

解决"平台绑架焦虑"。公众号是租的地，独立站是自己的地，做内容永生 + 出海载体。

专家洞察：四个空间的核心逻辑是 "利他→信任→资产"（FEN-001 信任成本铁律）的实体化。调研产出对准用户的内容，开源/站点沉淀可信作品，台账量化信任变现——它们共同把"行途"从一个写作者，运营成一个可评估、可传承、抗风险的自媒体资产。

07 调研与情报工作台 · L0 沉淀 + L4 调研 SOP

定位：所有"还没决定写不写"的情报先在这里加工，验证利他价值（FEN-001）后再进 02_内容仓库 灵感池。与 05_竞品参考 的区别：05 是被动剪藏的外部素材，07 是主动调研的产出。

08 开源与作品集 · L3 执行 + L4 开源 SOP

定位：开源不是炫技，是 IP 信任背书 + 反向引流钩子 + B2B 作品集（FEN-006"专业内容即作品集"）。每个项目都是一篇天然选题。

子结构规划

目录用途
<项目名>/每项目一子目录：源码 + README.md + 发布记录.md + 引流话术.md
仓库映射表.md项目 ↔ 仓库 URL ↔ 解读文章 ↔ 引流入口 ↔ Star 目标

🔧 项目子目录模板

  • 源码：正式仓库（GitHub 等），此处放说明性副本或子模块引用
  • README.md：开头一行定位 → 使用说明 → 结尾埋钩子（"更多一线 AI 工程化实践见公众号「行途」/ 知识星球"）
  • 发布记录.md：版本 / 日期 / 更新点 / 对应发布文章
  • 引流话术.md：README 钩子文案、社媒发布文案、各平台差异化摘要（复用 PUB-004）

🔧 仓库映射表字段

字段说明

仓库 URLGitHub / Gitee 等
对应解读文章发布后 24h 内必发"为什么做这个"（开源即选题）
引流入口README 钩子 / 文末 CTA
Star 目标量化里程碑（如 100 / 500 / 1k）
关联 STR挂靠技术实战主线
红线（发前必查）：SAF-006 商业机密——绝不提交任何任职公司代码、内部架构、未公开数据。开源内容须"通用化改造"。SAF-004 不碰现雇主、不写可定位细节。
专家洞察：开源项目 README 是零成本获客入口。一个被 Star 的工具，会在开发者搜相关词时反复曝光你——这是比公众号更"被动且精准"的流量。把它和 10 独立站、02 内容互相导流，形成"工具吸开发者→文章建信任→星球收口"的链路。

🔧 资源台账要点

  • 域名：注册商 / 到期日 / 自动续费开关（域名过期 = IP 资产瞬间清零，最高危）
  • 服务器/VPS：厂商 / 配置 / 到期 / 用途（独立站 10 依赖）
  • API Key：只记"在哪个环境变量/密码管理器/哪条记录"，正文绝不出现明文
  • 订阅/会员：飞书、各类 AI 工具订阅、CloudStudio 等，算月度成本
安全铁律：09_个人台账/凭据备忘.md 只能写"位置"（如"1Password 条目：xingtu-公众号-主邮箱"），任何明文密码 / Token / 身份证号都禁止写入。这与 SAF-003 安全第一、SAF-011 账号安全一致。台账文件建议 gitignore 或仅本地。
专家洞察：把粉丝当"可变现资产"而非虚荣指标。台账的真正价值是算清信任成本转化率——多少粉丝、多少进了星球、多少产生收入。没有这个表，你永远不知道哪个平台值得加注。

10 个人站点 · L3 执行 + L4 编排（网站即产品）

定位：公众号是"租的地"（规则随时变、封号归零），独立站是"自己的地"。核心价值：SEO 长尾永生 + 不被平台绑架 + 出海载体（Dev.to / Substack）。

子结构规划

目录用途
site-source/站点源码（静态框架，零成本优先）
domain-dns/域名 / DNS / HTTPS 证书配置
deploy/CI 自动部署配置（GitHub Pages / CloudStudio / Vercel）
content-sync/公众号↔站点↔出海 同步 SOP + 脚本
monitoring/uptime / SEO 排名 / 流量（umami 隐私友好）
运营笔记.md联动策略、防封备份、迭代记录

🔧 技术栈建议（专家视角）

框架：静态优先

Astro / Hugo / Next 静态导出。零服务器成本、易维护、SEO 友好。别一上来上重后端。

部署：白嫖 CI

GitHub Pages / CloudStudio / Vercel 自动构建。push 即上线，无需运维。

统计：隐私友好

umami 自托管 / Plausible，别用满屏追踪的 GA，符合 SAF-003 安全基调。

搜索：自带 + RSS

内置全文搜索 + RSS 订阅，把读者沉淀到站自有渠道。

🔧 内容同步策略（核心 SOP）

步骤动作规则
① 公众号首发拿原创、养搜一搜（PUB-003）PUB-003
② 独立站全文隔 6–24h 同步全文到站点，吃 SEO 长尾PUB-003
③ 出海改写精华改写英文发 Dev.to / Substack（记忆出海战略）—
④ 站反哺号站点文末挂公众号搜索词，把 SEO 流量导回搜一搜PUB-009
专家洞察（诺亚方舟逻辑）：独立站最大的价值不是流量，是抗风险。哪天某个平台改算法 / 封号 / 限流，你的核心内容仍在自己地里。把公众号爆款同步到站，等于给每篇内容买了"永生保险"。同时它是出海（Dev.to/Substack）的统一母舰。

⑥ 全链路闭环：四个空间如何咬合

它们不是并列文件夹，而是一条资产增值流水线。每个箭头都是一次"利他→信任→资产"的转化。

专家落地建议（优先级）

  • 先建 09：台账零成本、立刻防资产流失，且能为 10 站点/08 开源提供"成本-收入"数据底座。
  • 再建 07：调研模板直接提升 02 内容库的"可发选题"供给质量，短期 ROI 最高。
  • 然后 08 / 10：开源与站点需要持续投入，建议在有 1–2 个成熟工具/系列文章后再启动，避免烂尾。
  • 所有新建仍走 tools/safety/backup-before-op.sh 先快照、safe-delete.sh 替代 rm，遵守你"不 rm -rf + 先备份"铁律。

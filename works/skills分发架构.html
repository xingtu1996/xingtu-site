行途 Skills 分发架构

聚合管理 · 按需取用 · 独立演进 —— 不需要 1 个 skill 1 个仓

核心结论

标准做法 = 聚合仓 + 按名装单个。`xingtu-skills` 一个仓放 26 个 skill，外部用户只装 1 个时用：

npx skills add xingtu1996/xingtu-skills --skill find-skills（只装这 1 个）

npx skills add xingtu1996/xingtu-skills --all（装全部）

三种管理模式对比
推荐 · 现状

聚合仓（Monorepo）

所有 skill 一个仓，marketplace.json 索引。优点：统一管理、批量发布、AI 可整体检索；缺点：无法独立版本化单个 skill。

--skill <名字> 装单个
极端

全独立仓（1:1）

每个 skill 一个仓。优点：完全独立版本/发布/权限；缺点：26 个仓维护爆炸、检索碎片化、对齐成本高。只适合旗舰级 skill。

owner/<skill> 每仓 1 个
演进目标

混合（聚合 + 旗舰独立）

大部分 skill 留在聚合仓；1~2 个成长为旗舰资产的 skill 拆独立仓（保留聚合仓引用）。兼顾统一与独立。

聚合为主，旗舰独立
演进路径（0 → 1 → n）
0→1 聚合统一
26 skill 一个仓 + marketplace.json
对齐 Vercel skills 规范
→
1→n 按需取用
外部用户 --skill 只装 1 个
find-skills 可检索发现
→
旗舰拆独立
某 skill 火/需独立节奏时
拆独立仓 + 聚合仓留引用

生态运营
skills-lock.json 复现环境

阶段 2 不是必须的，只有 skill 成为核心资产才拆
独立管理的关键机制：marketplace.json（AI 可检索索引）+ skills-lock.json（跨环境复现）+ 独立仓独立版本号。现阶段聚合仓已 100% 满足"只取 1 个"需求。

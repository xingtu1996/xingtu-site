三、投喂口径：三分类 + 五问

丢进来不用整理，但公司内容必须先分类 —— 原始素材不分级入库 = 埋雷

三种投喂姿势（挑最省力的）

姿势适用怎么做
① 口述要点 推荐脑子里有货、懒得写直接说「2023 年我在团队群推 AI，当时……」，我来做卡
② 丢原始文件现成文档/截图/配置/聊天记录拖进 _inbox/ 任意子目录，说一句「这是 XX」即可
③ 丢链接公众号文章 / GitHub 仓 / 外链资料直接发链接，我抓
最低投喂单位：一句话 + 一个时间。比如「2024 年给公司搭了个 RAG 知识库，用的 X」—— 这就够开一张卡。

三个子目录怎么选

判断标准只有一个：这个东西如果原文发到公众号，会不会出事？

目录判定典型内容下游处理
01_可写原文发出去也没事个人技术实践、开源项目、工具配置、方法论直接提卡 → 可发布
02_待蒸馏有公司痕迹，但方法论可抽公司知识库建设、内部平台方案、团队流程改造抽规则不讲架构、去标识、量级化
03_仅供阅读给我看个背景，永不发布内部架构图、真实账单、同事信息、可定位细节只做理解上下文，不进任何对外产出
拿不准就丢 03_仅供阅读 —— 降级容易，泄露不可逆。

脱敏五问（SAF-004 / SAF-006）

丢公司相关内容前先过这 5 问，任一命中「是」→ 进 02 或 03：

1
含公司名 / 产品名 / 内部系统代号？
→ 蒸馏为「某供应链中台」「某零售企业」
2
含可定位的数字（数十个服务、千级权限点、真实账单）？
→ 量级化：「数十个微服务」「权限点四位数」「降到原 1/3」
3
含同事/上级姓名、群聊原文、内部截图？
→ 03 仅供阅读，只抽结论不引原文
4
含未公开的技术方案、架构图、源码？
→ 03 仅供阅读。只讲决策逻辑，不讲实现
5
涉及人事 / 绩效 / 纠纷 / 薪资？
→ 03 仅供阅读，永久封存
蒸馏唯一心法：讲规则，不讲架构；讲决策，不讲实现；讲量级，不讲数字。
❌「我们 数十个服务的工作流改造方案是……」 →  ✅「数十个服务的工作流改造里，我定了 3 条铁律：事务内禁止远程调用、列表强制分页、SQL 强制参数化」

五、待填卡槽：对着答就行

每题答一两句即可，答不出就划掉。目标 8–10 张卡，不是 20 张

A 组 · 知识库 / RAG 最高优先

  • A1 起点：什么时间？老板派的还是你发起的？当时痛点是什么
  • A2 角色：执行者 / 带队者 / 布道者？管几个人
  • A3 选型：用了什么、放弃什么、重来会改哪
  • A4 踩坑：最大的坑？有没有"方向错了"的时刻
  • A5 效果：怎么判断做成了（量级即可，没数字就跳）
  • A6 人的因素 最值钱：抵触声音是什么、怎么破的、现在用得怎样
  • A7 方法论：换家公司重做，先做哪三件事？有什么反常识经验

B 组 · MCP 实践

  • B1：用过/搭过哪些 server，哪些是自己写的
  • B2：哪些活下来了、哪些吃灰、为什么
  • B3：有没有把内部系统包成 MCP？最大障碍是什么
  • B4：你判断"该不该做成 MCP"的标准是什么

C 组 · 团队 AI 布道（2023 至今）

  • C1 时间线：什么时候开始、什么形式
  • C2 阻力：最大阻力是什么、怎么破的、有转化的例子吗
  • C3 现状：使用率什么量级？重来第一步会做什么不同的事
建议顺序：先答 A6（人的因素） 和 A4（踩坑） —— 这两题的答案几乎必然是别人写不出来的内容，也是最容易直接变成爆款选题的。
A3（技术选型）反而最不急，因为技术细节同质化最严重、最容易被抄。

一、图片制作偏好

封面 / 配图 / 海报的生产方式、配色、尺寸、审美

生产方式（方法论已定稿）核心

  • 封面 / 配图 / 海报一律用 HTML/CSS 排版 → Chrome headless 截图成 PNG，禁止 PIL 手排坐标（PIL 算坐标容易「乱」、无法精确控制对齐/字号/留白/层次）。
  • 数据图 / 信息图 → 代码精确排版（matplotlib / HTML+CSS），零 AI 味、最专业。
  • 文生图（ImageGen）→ 只在需要「照片 / 插画感」时用；注意右下角有内置水印需裁剪（B09 封面中心裁剪 1536×1024→900×383 消水印）。
  • canvas-design skill 用于「视觉艺术」类（封面 v2 Geometric Silence / v3 SignalDistilled）。
关键跃迁（永久规则）：B09 阶段用 PIL 手排 → A0 阶段 boss 反馈「乱、格式不对」→ 改 HTML/CSS + Chrome 截图。截图命令模板：--headless --no-sandbox --force-device-scale-factor=2 --window-size=W,H --screenshot=out.png；Bash 需 dangerouslyDisableSandbox:true；HTML class 名不能带连字符（否则 CSS 选择器不匹配）。

配色系统（行途蓝主题）

  • 主品牌色 行途蓝 #056DE8 · 亮蓝提亮 #4A9EFF · 青色辅色 #00D4FF · 对比橙 #FF6B35（次要/警示）。
  • 封面 SignalDistilled 用 深空近黑底 + 单一主色（亮蓝数字）——「暗室里一束被校准过的光」。
  • 层级图要多色「跳色」（①深蓝②亮蓝发光③紫④橙⑤青⑥绿），禁同色系微渐变（区分度低）。

尺寸规范

用途尺寸说明
公众号头条封面900 × 383（2.35:1）最终 PNG 常为 1800×766（@2x）
图片消息 / 贴图900 × 900（1:1 方形）缩略图裁方形，横版会被裁变形
正文配图900 × 580 / 470 / 560按内容定，900 宽统一

封面审美（SignalDistilled · 信号蒸馏）

  • 哲学：剥离冗余、只留信号——压倒性负空间 + 一个超大数字承载全部信息 + 文字压到最小只做锚点。
  • 落地：超大「97.7%」（亮蓝、左对齐重量感）+ 微小「0.4%」（右下暗色注解，形成悬殊对比）+ 极细基线 + 克制标题副题。
  • 通用规则：大字号大留白、小图可读；参考量子位/机器之心风格（大标题主导 + 深色纹理 + 单一图形焦点）。

二、内容偏好

写作铁律 + 结构 + 标题 + 诚实与合规

写作铁律（6 条，长期有效）

  • 真实为本：核心差异化 = 一线工程实践 + 真实账单/数据，不追黑科技，胜在可信。
  • 权威锚点：用可查证的业内共识背书（Rich Sutton 2019 / Anthropic 2025 / Karpathy），严禁编造大佬名言。
  • 思想经久：卖「思想」不卖「配置/工具」——工具会变（Claude/Codex/WorkBuddy/豆包），思想跨工具成立。
  • SEO + AI 友好：标题前 13 字含核心词、开头 100 字埋词、小标题含词、密度 2–4%、「一句话结论」做 GEO 锚点。
  • 出书预备：每篇攒「真实数据 + 可复现提示词 + 思想」，长期结集出书。
  • 实践性强：给能直接抄的清单/代码/配置，落「利他」。

结构：3 段法（思想锚点 → 工具实现 → 思想升华）

思想锚点（开篇立理念）→ 工具实现（真实配置/实测）→ 思想升华（结尾金句呼应）
  • 每篇 保 1 个「理念型」金句（可引用记忆锚点），如「模型贵在想，不贵在搬」「省 token 不是让 AI 少说，是让 AI 少看」。
  • 思想层 vs 工具层要分明，「术」不混「道」（方法论段压脚注，不占正文）。

标题 & 诚实 & 合规

  • 标题「讲道」：要第一性原理感、一眼专业不明觉厉，不要纯数据钩子（boss 纠正过：数据钩子版 → 第一性原理版）。
  • 诚实差异点：不吹单边，如实写（如 GLM 缓存命中场景 DeepSeek 更便宜，照写）。
  • 数据口径声明：数量口径 vs 费用口径必须写清（0.4% 是数量，费用口径约 14.6%）。
  • 数据脱敏：公司/团队账单公开只留量级（上百亿 token / 几十个人），精确值 + 费用金额不公开。
  • 私域钩子无条件（公众号回复「六层」自取，无在看门槛，避诱导红线）。
  • 返利邀请链接分平台（公众号原文链接可放，掘金删，避「诱导交易」红线）。

三、提示词偏好（人 + AI 协作方法论）

跟 AI 协作产出内容时的提示词/工作流约定

写作协作提示词流水线

AI 扒数据（WebSearch 多源交叉）→ 结构化提示词拆骨架→ 人工定调补引用（去 AI 味 / 定标题 / 补权威锚点）
  • 数据先问 boss 拿真实值，不凭印象估（教训：曾把「195 亿 token」低估 100 倍写成「大几千万」）。
  • 权威引用 WebSearch 核实，严禁编造；工具给 GitHub 链接 + 实时 star（GitHub API 实时拉取，非猜非转述）。
  • 图片用代码/HTML 精确排版，不写文生图提示词（文生图只留照片/插画感场景）。
  • 多 Agent 对抗审查（adversarial-review，5 专家并行：IP/harness/token/UI 视觉/SEO 合规）交叉验证。
提示词框架模板已作为私域钩子资产（公众号回复「六层」自取）：六层落地清单 + token 踩坑卡 + 提示词框架模板——是「真实数据 + 可复现提示词 + 思想」出书预埋的一环。

四、纠偏调优偏好

从「初稿 → 定稿」反复打磨中的纠偏轨迹与铁律

封面迭代链（13 版，纠偏轨迹）

v1 朴素 v2 Geometric Silence v3 SignalDistilled（"乱、格式不对"） V-A 环形图 V-B 大数字 V-C 六层 V-D 金句 V-动漫 M1 左图右文 M2 动漫底浮层 G1 黄金比例 G2 主体优先 G3 内容展开 ✅ 最终
纠偏路径：PIL 手排「乱」→ boss 要「亮堂点、科技点」→ 4 版亮色科技风 → 回归 SignalDistilled「信号蒸馏」深色大数字。教训沉淀为「HTML/CSS 排版 + Chrome 截图」永久规则。

多 Agent 审查真发现（7 处已修）

  • 命令错误：rtk 安装命令 `brew install rtk-ai/tap/rtk` → 实为 `brew install rtk`；`rtk init --global` → `rtk init -g`。
  • 数据口径缺声明：0.4%/97.7% 补「数量 vs 费用」blockquote。
  • 实测口径：Headroom「实测 20-95%」→「开源项目实测…随任务类型波动」。
  • 概念窄化：缓存读「常驻前缀」→ 扩为「对话历史/工具结果/系统提示词」。
  • 图 1 视觉硬伤：金句与 X 轴重叠、无网格 → 重做（Y 轴刻度 + 网格 + 金句移出）。
  • 数字口径：80% vs 94% 补「CodeGraph 官方另有 94% 口径」。
  • 无出处数据：遵从率 70-90% 补「随任务与表达方式波动，非精确值」。

去 AI 味（de-ai-flavor，5 处改写 + 2 处保留）

改写前（AI 味）「工具会变，思想不变」「省 token 要依靠机制，不依靠嘱咐」「少而精胜于多而杂」「真正的杠杆是思想不是配置」「攒够了就是一本书」
改写后（具体 + 数字 + 代价）「同一套 hook，从 Claude Code 拆下来装到 Codex 照用不误」「20 条规矩实测只执行七到九成，不如上 hook」「128K 塞七成噪音不如 32K 干净」「配置三个月过期，思想今天还能用」「一周 1-2 篇，下篇拆检索层」
保留 2 处思想锚点（有信息量、可引用）：「模型贵在想，不贵在搬」「省 token 不是让 AI 少说，是让 AI 少看」——对仗但信息密度高，是系列记忆锚点，不改。

其他纠偏铁律

  • 标题纠偏：数据钩子版 → 第一性原理「讲道」版（boss 明确「要讲道」）。
  • 术不混道：「附：我们怎么跟 AI 写这篇」整段删，压成文末脚注。
  • mermaid 必须转图：公众号不显示 mermaid，用 PIL/HTML 自绘等价 PNG（比 mermaid.live 更可控）。
  • 发布节奏：双锚点（早 8:15 轻内容贴图 + 晚 20:00 深度长文），停凌晨 3 点发文习惯。
  • 私域钩子去门槛：「点在看后私信」→ 无条件回复（避诱导边缘）。

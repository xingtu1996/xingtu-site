正文（可直接粘贴；表格先经 Markdown 渲染工具转富文本）

用 AI 编程工具久了，账单才是真正的"沉默成本"。上周翻 token 账单，我盯着输出侧的数字愣了一下——比预想的厚了不少。翻了一圈官方文档才发现：很多东西其实都写着，只是没人翻。我把 Claude Code 的回复配置从默认改成 Concise，又调了一个压缩阈值，实测下来，输出侧肉眼可见地瘦了。这篇一次性讲清楚。

先给一个判断：AI 编程烧钱，绝大多数时候不是"用太多"，是"配置没对"。 工具的成本有一半藏在配置里，而配置这层，恰恰是大多数人从不翻开的那页说明书。下面讲的就是翻开之后看到的东西——一个 5 分钟能改完、零成本、纯官方能力的配置。

一、核心发现：outputStyle（输出样式）

先看官方定义——输出样式改变的是 Claude 的「响应方式」，不是它「知道什么」。它通过修改系统提示词，设定角色、语气和输出格式。

官方内置 5 档风格（按自己阶段随时切，/config 里就能看到）：

档位官方定位适合谁
Default默认 system prompt，高效完成软件工程任务通用
Proactive立即执行、合理假设、爱行动胜过计划熟手赶进度
Concise先给结果、跳过铺垫、默认简短省钱 / 要效率
Explanatory边做边讲，加教育性 Insights学习期 / 带新人
Learning协作式边学边做，留 TODO(human) 让你自己写刻意练习
【插入配图】图2_五档风格.png（outputStyle 5 档竖排，Concise 高亮）

两种调整方式（二选一即可）：
1. 命令方式：敲 /config → 选 Output style → 自动保存到项目级 .claude/settings.local.json（只影响你自己、只在这个项目）
2. 文件方式：直接编辑 settings.json，加一行 "outputStyle": "Concise"

注：旧教程里的 /output-style 命令已在 v2.1.73 废弃、v2.1.91 移除，现在只有上面两条正路。

下面聚焦省钱最狠的 Concise 这一档：

项值

值"Concise"
引入版本v2.1.237+，没有环境变量形式

【插入配图】图3_Concise前后对比.png（左「默认：复述需求→计划→代码→总结」右「Concise：代码 + 1 行说明」）

关键认知：Concise 是"系统级默认声音"，和你只是口头说"简短点"不一样——它是写进 system prompt 的兜底。它和另一个叫 Caveman 的强压缩技能是互补关系：Concise 管日常默认简洁，Caveman 管极端场景的 ~65% 压缩。

二、Token 节省配置清单（逐条可抄）

配置位置当前建议作用
outputStyle: "Concise"settings.json未设✅ 加输出 token 系统级减少
CLAUDE_CODE_AUTO_COMPACT_WINDOWenv/settings1048576（顶到 1M）800000压缩阈值留缓冲，对齐 80% 标准
skillListingMaxDescCharssettings.json1024 ✓保持skill 描述截断（输入侧）
skillListingBudgetFractionsettings.json默认 0.01保持skill 列表占比上限
CLAUDE_CODE_EFFORT_LEVELenv未设可选降 effort 省 token（会降质量，谨慎）
MAX_THINKING_TOKENSenv未设可选deepseek 路由关思考省 token
BASH_MAX_OUTPUT_LENGTHenv默认 30000可调bash 输出截断（间接省）

我的实测决策（2026-08-25）：

  • outputStyle: Concise → 加入（用户级 settings），兜底日常简洁，安全内容保留
  • AUTO_COMPACT_WINDOW 1M → 下调到 800k，避免贴上限触发压缩
  • EFFORT_LEVEL / THINKING → 暂不，降 effort 影响质量，先观察
【插入配图】图4_省token数据对比.png（rtk 93.6% > Caveman 81% > CBM 80% > Ponytail 73% > Codex 40-60% > Headroom 20-95%）

⚠️ 一个坑：Concise 下模型不写 plan、不复述。如果你们团队 review 依赖"它复述一遍计划"，体验会变（官方 issue 里有人吐槽）。建议先在非关键会话试跑。

三、多模型适配注意（deepseek[1m] 用户必看）

如果你像我一样用带 [1m] 后缀的模型（比如 deepseek[1m]），有两个坑：

  • 模型 ID 含 [1m] 时，CLAUDE_CODE_MAX_CONTEXT_TOKENS 不独立生效——必须设 CLAUDE_CODE_DISABLE_1M_CONTEXT=1 才能覆盖
  • AUTO_COMPACT_WINDOW 默认 1M = 压缩点顶到极限，调到 800k 才合理

四、一句话抄作业

1. settings.json 加 "outputStyle": "Concise"
2. 环境变量把 AUTO_COMPACT_WINDOW 设 800000
3. 用 deepseek[1m] 的，记得 DISABLE_1M_CONTEXT=1 才能调上下文上限
4. 先用非关键会话试跑，确认团队 review 体验不吃亏

这 4 条，零成本，纯官方能力。AI 编程的成本，很多时候不是"用太多"，是"配置没对"。

延伸 · Concise 只是「散文层」的一环

这篇讲的 Concise 只省「输出侧」——让回复变短。但 AI 编程的 token 大头其实在「输入侧」：反复读文件、冗长日志。我们团队把它拆成 6 层，每层一个工具、一层实测：
